# Constraints & Indexes

Sumber: `pg_constraint` (dengan `pg_get_constraintdef`), `pg_indexes`, `information_schema.sequences`, dan info identity.

## Primary Keys

| Tabel | Constraint | Definisi |
|---|---|---|
| `barang` | `barang_pkey` | `PRIMARY KEY (id)` |
| `stock_levels` | `stock_levels_pkey` | `PRIMARY KEY (id)` |
| `transaksi` | `transaksi_pkey` | `PRIMARY KEY (id)` |
| `profiles` | `profiles_pkey` | `PRIMARY KEY (id)` |
| `user_sessions` | `user_sessions_pkey` | `PRIMARY KEY (user_id)` |

## Foreign Keys

| Constraint | Definisi |
|---|---|
| `profiles_id_fkey` | `FOREIGN KEY (id) REFERENCES auth.users(id) ON DELETE CASCADE` |
| `transaksi_user_id_fkey` | `FOREIGN KEY (user_id) REFERENCES auth.users(id)` |
| `user_sessions_user_id_fkey` | `FOREIGN KEY (user_id) REFERENCES auth.users(id) ON DELETE CASCADE` |
| `stock_levels_item_id_fkey` | `FOREIGN KEY (item_id) REFERENCES barang(id) ON DELETE CASCADE` |
| `transaksi_barang_id_fkey` | `FOREIGN KEY (barang_id) REFERENCES barang(id)` |

## Unique Constraints

| Tabel | Constraint | Definisi |
|---|---|---|
| `stock_levels` | `stock_levels_item_id_warehouse_kriteria_key` | `UNIQUE (item_id, warehouse, kriteria)` |
| `transaksi` | `transaksi_client_tx_id_key` | `UNIQUE INDEX ... (client_tx_id) WHERE (client_tx_id IS NOT NULL)` (partial) |

> `transaksi.client_tx_id` diimplementasikan sebagai **partial unique index** (bukan constraint), supaya banyak baris `NULL` dibolehkan.

## Check Constraints

| Tabel | Constraint | Definisi |
|---|---|---|
| `profiles` | `profiles_role_check` | `CHECK (role = ANY (ARRAY['staff'::text, 'guest'::text]))` |
| `stock_levels` | `stock_levels_kriteria_check` | `CHECK (kriteria = ANY (ARRAY['Good'::text, 'Bad'::text]))` |
| `stock_levels` | `stock_levels_warehouse_check` | `CHECK (warehouse = ANY (ARRAY['Puri'::text, 'CS TCL'::text, 'CS SBF'::text]))` |
| `transaksi` | `transaksi_jenis_check` | `CHECK (jenis = ANY (ARRAY['masuk'::text, 'keluar'::text]))` |
| `transaksi` | `transaksi_jumlah_check` | `CHECK (jumlah > 0)` |
| `transaksi` | `transaksi_kriteria_check` | `CHECK (kriteria = ANY (ARRAY['Good'::text, 'Bad'::text]))` |
| `transaksi` | `transaksi_warehouse_check` | `CHECK (warehouse = ANY (ARRAY['Puri'::text, 'CS TCL'::text, 'CS SBF'::text]))` |

## Indexes (pg_indexes)

| Tabel | Index | Definisi |
|---|---|---|
| `barang` | `barang_pkey` | `UNIQUE btree (id)` (via PK) |
| `profiles` | `profiles_pkey` | `UNIQUE btree (id)` (via PK) |
| `stock_levels` | `stock_levels_pkey` | `UNIQUE btree (id)` (via PK) |
| `stock_levels` | `idx_stock_levels_item` | `btree (item_id)` |
| `stock_levels` | `stock_levels_item_id_warehouse_kriteria_key` | `UNIQUE btree (item_id, warehouse, kriteria)` |
| `transaksi` | `transaksi_pkey` | `UNIQUE btree (id)` (via PK) |
| `transaksi` | `transaksi_client_tx_id_key` | `UNIQUE btree (client_tx_id) WHERE client_tx_id IS NOT NULL` |
| `transaksi` | `transaksi_created_at_id_idx` | `btree (created_at DESC, id DESC)` |
| `transaksi` | `transaksi_barang_created_id_idx` | `btree (barang_id, created_at DESC, id DESC)` |
| `user_sessions` | `user_sessions_pkey` | `UNIQUE btree (user_id)` (via PK) |

> Index `transaksi_created_at_id_idx` dan `transaksi_barang_created_id_idx` mendukung pola `order('created_at', { ascending: false })` + `order('id', { ascending: false })` yang dipakai frontend di halaman riwayat, dan RPC `riwayat_balance_before` (dijelaskan di functions.md).

## Identity & Sequence

| Sequence | Data type | Start | Min | Max | Increment | Cycle | Owner |
|---|---|---|---|---|---|---|---|
| `barang_id_seq` | bigint | 1 | 1 | 9223372036854775807 | 1 | false | `barang` (identity) |
| `stock_levels_id_seq` | bigint | 1 | 1 | 9223372036854775807 | 1 | false | `stock_levels` (identity) |
| `transaksi_id_seq` | bigint | 1 | 1 | 9223372036854775807 | 1 | false | `transaksi` (identity) |

Mode identity:
- `barang.id` → `GENERATED ALWAYS AS IDENTITY` (insert aplikasi tidak mengirim `id`)
- `transaksi.id` → `GENERATED ALWAYS AS IDENTITY`
- `stock_levels.id` → `GENERATED BY DEFAULT AS IDENTITY` (memungkinkan override `id`)

> `profiles.id` dan `user_sessions.user_id` adalah UUID (diisi aplikasi/auth trigger), tidak memakai sequence.

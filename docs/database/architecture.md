# Arsitektur — stock_sdi_demo

Sumber kebenaran: `supabase-snapshot/` (schema, indexes, triggers, functions).
Homelab mereplikasi **struktur + business logic**, dengan sekali perubahan desain
pada domain user (lihat bawah).

## Skema (4 tabel)

```
profiles  (id uuid PK, nama text, role check staff|guest)
barang    (id bigint GENERATED ALWAYS identity PK, nama, stok int default 0, updated_at tstz)
stock_levels (id bigint GENERATED BY DEFAULT identity PK,
              item_id FK -> barang.id ON DELETE CASCADE,
              UNIQUE(item_id, warehouse, kriteria),
              warehouse check Puri|CS TCL|CS SBF,
              kriteria check Good|Bad, jumlah numeric, updated_at)
transaksi (id bigint GENERATED ALWAYS identity PK,
           barang_id FK -> barang.id (NO ACTION),
           jenis check masuk|keluar, jumlah int check >0,
           warehouse default Puri, kriteria default Good,
           user_id uuid NULL, client_tx_id uuid NULL, keterangan, created_at)
```

## Index

- `idx_stock_levels_item` (item_id)
- `transaksi_created_at_id_idx` (created_at DESC, id DESC)
- `transaksi_barang_created_id_idx` (barang_id, created_at DESC, id DESC)
- `transaksi_client_tx_id_key` UNIQUE partial (client_tx_id IS NOT NULL) — jaga idempotensi client

## Fungsi & trigger (body sama persis dari snapshot `functions.sql`)

| Fungsi | Trigger | Peran |
|---|---|---|
| `seed_stock_levels_barang()` | `trg_barang_seed_saldo` (AFTER INSERT barang) | Buat row stock_levels Puri/Good = stok awal dari `barang.stok` (skip bila 0) |
| `sync_saldo_transaksi()` | `trg_transaksi_sync_saldo` (AFTER INSERT transaksi) | - Tolak keluar jika saldo warehouse+kriteria kurang (ERRCODE `check_violation`); upsert saldo; sinkron `barang.stok = SUM(stock_levels)` |
| `riwayat_balance_before(bigint, timestamptz, bigint)` | — | RPC read-only untuk ekspor riwayat (saldo sebelum transaksi, tie-break id) |
| `update_stok_barang()` | **tidak dipasang** | Kode mati di Supabase; dibuat untuk kompatibilitas referensi, tidak boleh dipakai API |

## Alur bisnis (dijamin validasi)

1. Insert `barang` → seed Puri/Good (hanya jika stok ≠ 0).
2. Insert `transaksi` masuk → +jumlah pada warehouse+kriteria dan stok barang.
3. Insert `transaksi` keluar → -jumlah, ditolak bila saldo lokasi tidak cukup.
4. Total stok barang selalu = SUM semua `stock_levels` untuk item itu.

## Perubahan desain vs Supabase (keputusan)

| Aspek | Supabase | Homelab |
|---|---|---|
| `profiles.id` | FK → `auth.users(id)`, dibuat oleh trigger auth | uuid PK, **tanpa** FK auth; diisi API auth custom (tahap berikut) |
| `transaksi.user_id` | DEFAULT `auth.uid()` FK → auth.users | NULL, tanpa default/FK; diisi API auth nanti |
| RLS (11 policy) | aktif | tidak dibuat; authorization via API layer |
| Realtime publication | `supabase_realtime` (public.barang) | tidak dibuat; polling dari API |
| `handle_new_user` / `on_auth_user_created` | ada | ditunda sampai desain auth  |
| Extensions (`uuid-ossp`, `pgcrypto`, ...) | ada | tidak dibuat (tidak diperlukan schema)
